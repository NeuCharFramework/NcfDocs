# 后台日志查询与排障

<a id="help-logs"></a>

## 日志

按日期选择相关日志文件，将时间与失败操作对应起来。
浏览器 Console 与服务器日志是不同来源。分享诊断片段前，
请移除令牌、凭据、个人数据和私有文档内容。

<a id="help-log-details"></a>

## 指定日期的日志详情

此页查看选定日期的 SenparcTrace 文件，可切换完整结果/异常信息，并按关键字、开始与结束时间、
线程、类型和异常状态筛选。行号、时间、标题及内容用于定位一条记录，不是重新执行请求的入口。
“没有结果”可能是筛选范围内没有匹配项；排查前先核对日期和筛选条件。

列表以分页摘要返回，打开某一行可查看已脱敏的详情。响应禁止缓存，日期必须使用 `yyyyMMdd` 格式。
系统会将密码、授权请求头、Bearer Token、Cookie 及常见密钥字段等可识别敏感内容替换为 `***`。
脱敏只是纵深防护，应用本身仍应避免把密钥、个人数据或私有文档写入日志。

<a id="help-ai-log-analysis"></a>

## 使用 AI 分析日志

在日志详情页点击底部的 **AI** 按钮后，AdminChat 输入框会逐字填入包含当前日期的命令，并保留末尾空格，
可以继续输入问题：

```text
/analyze-system-logs --date=yyyyMMdd
```

也可以在 AdminChat 中直接发送：

```text
/analyze-system-logs --date=20261123 今天有多少异常，主要原因是什么？
```

未指定 `--date` 时使用服务器当天日期。该命令只为当前请求追加系统日志工具，不需要用户手动选择
AdminChat 模块或 Workspace。

分析流程明确限制证据范围，以减少 Token 消耗：

1. 首先调用 `GetSystemLogOverview`，返回总量、类型统计、日志时间范围，最多 10 个异常签名和最多
   10 个线程统计。
2. 使用 `SearchSystemLogs` 按关键字、日志类型、异常状态或线程缩小范围，每次最多返回 30 行。
3. 仅对与结论直接相关的行号调用 `GetSystemLogEvidence`。常规分析最多读取 6 条记录、每条 4,000
   字符；服务端对单条记录设置了 8,000 字符硬上限。
4. 如果概览已足以回答，AI 不再加载详情；结果过多时必须先细化筛选，而不是扩大读取范围。

该流程适合日志摘要、异常计数与分组、时间段关联、线程/类型分析、关键字追踪、重复故障比较和
可能原因建议。结论应附带可用的日期、时间、行号和线程证据，并明确区分观察事实与推测；文件缺失、
筛选无匹配或日志不完整时，应说明限制，而不是补造结论。

此命令为只读操作，不会修改日志、执行 Shell 命令、变更数据库或重放请求。系统日志 Function 受
Admin 权限策略保护，只返回脱敏数据。若分析需要跨系统证据、原始密钥或不完整的归档日志，应由
运维人员按照组织访问策略导出相关证据后人工复核。
