# AIKernel 模型、向量与用量管理

<a id="help-ai-models"></a>

## AI 模型配置

选择服务提供商，填写端点、模型/部署名称及必需凭据。
聊天模型与 Embedding 模型用途不同，应为调用方选择兼容配置。
排查提示词之前，先确认连接和提供商的配置要求。凭据必须保密。

### 第一次配置模型

第一次安装时建议一次只配置一个模型：

1. 选择实际持有凭据和端点的服务商。
2. 填写服务商要求的准确模型名或部署名。友好别名只用于 NCF 的显示和选择，
   不会改变服务商侧的模型名称。
3. 根据调用方选择能力：聊天模型用于对话，Embedding 模型用于知识库检索向量。
4. 只在受保护的编辑窗中填写端点和 API Key，保存后先执行最小测试。
5. 在实际功能中选择已保存模型，成功完成一次真实请求后再继续增加模型。

浏览器能打开端点，不代表 API 兼容。还要检查服务商路径、认证请求头、部署名、
API 版本、配额和服务器出站网络策略。编辑窗中已掩码的 API Key 留空表示继续使用
原值；要替换必须输入新值。

## 向量存储配置

选择后端并配置连接，再由知识库引用。下拉框中存在某个选项，
不代表外部数据库已经安装或连通。这里的 `Memory` / `VolatileInMemory` 是进程内向量后端，
不是 AdminChat 的长期 Memory；内存后端连接字段应留空，不适合作为持久生产存储。
更换 Embedding 模型或向量配置可能需要重建索引；变更前备份需要保留的数据。

### 安全选择后端

进程内后端只适合开发或可丢弃测试。持久知识库应选择受支持的持久化后端，
从 NCF 所在主机验证连接，并在导入文档期间保持 Embedding 模型稳定。
更换 Embedding 模型后，新旧向量可能无法比较；应安排重新向量化窗口，
不要静默混用两套模型。

<a id="help-ai-tokens"></a>

## Token 监控

通过 Token 监控查看已记录的模型用量及对应筛选结果。
Token 数不是字符数、文件大小或本地文本抽取上限。
缺少监控记录不能证明没有发生服务商调用，涉及费用时应与服务商账单核对。

Token 监控是观测页，不是服务商实时账单页。建议先选择模型和短提示词执行一次小测试，
再核对调用次数、输入 Token、输出 Token、总 Token、耗时和状态。
服务商请求成功但页面没有记录时，应分别检查所选模型、用量持久化、应用日志和服务商记录。

<a id="help-ai-dashboard"></a>

## AI 仪表盘

仪表盘用于概览已配置 AI 资源及已记录用量；详细情况转到模型、向量或 Token 页面。
解释汇总数据前先确认时间范围及实际可用数据。
