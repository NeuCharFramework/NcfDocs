# KnowledgeBase 知识库与召回测试

<a id="help-knowledge-base"></a>

## 知识库与向量化

1. 新建知识库，选择 Embedding 模型和向量存储。
2. 在配置中关联需要检索的资料。
3. 执行“向量化”，检查结果并处理失败，再进入测试。
4. 用真实问题做召回测试，同时检查原始来源。

修改资料或 Embedding 配置，不代表存储的向量已经更新，应按需重新构建。
将内容发送给外部 Embedding 服务前，先确认资料访问权限和保留要求。

<a id="help-knowledge-create"></a>

## 新建知识库

“新建知识库”打开名称及模型配置表单，选择 Embedding 模型、向量数据库和需要的对话模型。
Embedding 用于生成检索向量，对话模型用于生成回答，两者不能互相替代。
保存知识库定义后，还要在“配置”中关联资料并执行“向量化”；点击新建或保存并不会完成整个入库过程。

<a id="help-knowledge-recall"></a>

## 召回测试与 Top K

选择已向量化的知识库，输入真实问题，检查返回片段、来源名称、链接及排序。
“查看全文”打开片段详情；历史表记录测试问题、知识库、片段数、最高相似度和测试时间。

相似度分数是排序参考，**不是召回率百分比，也不是答案正确概率**。
不同模型、后端的分数尺度可能不同。启用重排时，区分重排分数/顺序与原始向量排序。
判断前查看完整段落；一次问题测试成功不能证明整个知识库都已达到质量要求。

<a id="help-knowledge-top-k"></a>

## 返回片段数量（Top K）

“检索设置”中的滑块和数字输入框控制当前页面后续召回测试的返回片段上限，
范围 **1–20**，建议先从 **5** 开始。结果不足可提高，噪声过多可降低。
Top K 不是相似度阈值、召回率或知识库总文档数；修改它不会重新向量化，也不会修改全局模型参数。
