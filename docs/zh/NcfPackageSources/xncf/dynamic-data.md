# DynamicData 数据表、布局与页面

<a id="help-dynamic-data"></a>

## DynamicData

按数据表定义、布局、页面配置/渲染的顺序构建动态界面。
模块首页可能仅展示生成模块信息，实际编辑应进入具体配置页。
面向其他用户开放前先用可丢弃的测试数据验证。

<a id="help-dynamic-tables"></a>

## 动态数据表

定义数据表和字段，包括标识、类型、必填/唯一约束及展示元数据。
更改结构前检查现有数据，界面验证不能代替后端验证。

### 小白操作顺序

1. 创建数据表并使用稳定、容易识别的名称。
2. 先添加字段，再创建布局；确定哪个字段是标识、哪些字段必填或唯一，
   以及哪些值可以展示给用户。
3. 导入或导出前检查字段映射，并为重要数据保留备份。
4. 进入“创建布局”，把每个显示列或表单项绑定到目标字段，再明确配置排序、
   编辑、删除和导出动作。
5. 在“界面设置”中关联布局，用代表性数据预览，确认后再发布。

修改字段名称或类型可能使已保存布局的绑定失效。结构变化后应重新检查所有相关布局
和页面，不能只看预览是否成功。

<a id="help-dynamic-layouts"></a>

## 动态布局

先选择数据源并绑定列/字段，再配置按钮、事件、弹窗和导航。
在预览中逐项验证绑定；按钮名称不能决定效果，应检查实际配置的动作。

<a id="help-dynamic-pages"></a>

## 动态界面设置

将目标布局关联到页面，并用代表性数据检查渲染结果。
这里管理页面与布局的关联；直接操作生成表单应进入动态布局渲染页。
发布前核对查询、编辑、验证和导航行为，预览成功不代表获得了数据访问权限。

页面关联与数据权限要分开检查。页面可以对管理员正常渲染，但不一定适合普通用户。
发布前确认路由、租户范围、增删改动作以及服务端授权。

<a id="help-dynamic-render"></a>

## 动态布局渲染页

此页按已保存布局展示表格或表单，“提交”“重置”等按钮由布局配置决定。
它不是布局设计器；要修改字段、按钮或事件，请回到“数据表设置”“布局设置”或“界面设置”。
先核对页面对应的布局和数据源，再测试提交，不能把动态界面可见性当作数据访问授权。

表单提交失败时，先确认所选布局仍存在、必填字段都已绑定、当前用户对目标数据具有写入权限。
如果只有预览成功而提交被拒绝，应检查服务端验证和字段类型；修改浏览器控件不能绕过后端规则。
